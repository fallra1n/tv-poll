## Задача для тестового для бэка

Мы - национальная компания по проведению опросов, запускаем минутные ролики на крупнейших тв канал, где показываем опрос (1 вопрос любого типа: multiple choice, a/b, ...) и просим зрителей пройти по куар коду / ссылке и проголосовать.

Опросы не требуют регистрации, но надо предусмотреть дедупликацию базовую (не слишком защищенную от обхода, достаточную на уровне обычных, не технически подкованных пользователей), чтоб не накручивали голоса

Каждый ролик смотрит примерно 100М человек, длится он около минуты, в течении которой они могут голосовать

На нашей стороне мы хотим иметь возможность создавать опросы и смотреть обезличенные результаты

### Что должно быть результатом решения задачи

Бэкенд сервис (опционально - с фронтенд составляющей), который предоставляет возможность:

- анонимно проголосовать
- создать опрос (админка)
- посмотреть результаты опроса (админка)

Использование ИИ поощряется

### Что должно быть при сдаче задания

1. Описание сервиса, как его запустить локально и протестировать
2. Обоснование выбранной архитектуры и технологий
3. Все артифакты работы с ИИ должны быть в сдаваемом репозитории, не надо их скрывать

### Формат сдачи

публичный репозиторий на гитхабе / гитлабе

## Что я вычитываю из задания

Явные требования:

| # | Требование | Источник |
|---|---|---|
| R1 | Анонимное голосование без регистрации | «Опросы не требуют регистрации» |
| R2 | Базовая дедупликация, защита от обычного пользователя, не от специалиста | «не слишком защищенную от обхода» |
| R3 | Один вопрос на опрос, тип вопроса произвольный | «1 вопрос любого типа» |
| R4 | Окно голосования ~1 минута | «длится он около минуты» |
| R5 | Порядок 100М потенциальных участников | «примерно 100М человек» |
| R6 | Админка: создание опроса | список результатов |
| R7 | Админка: просмотр результатов | список результатов |
| R8 | Результаты обезличены | «обезличенные результаты» |
| R9 | Локальный запуск и способ протестировать | п.1 сдачи |
| R10 | Письменное обоснование архитектуры | п.2 сдачи |
| R11 | Артефакты работы с ИИ в репозитории | п.3 сдачи |

Неявные, но следующие из контекста:

- **R12.** Момент пиковой нагрузки известен заранее (сетка вещания) — это
  меняет стратегию масштабирования, см. `02-load-model.md`.
- **R13.** Анонимность (R1/R8) и дедупликация (R2) конфликтуют: любой признак,
  по которому мы узнаём повторного голосующего, — это идентификатор.
  Разрешение конфликта должно быть описано явно.
- **R14.** Заказчик — опросная компания. Ложноположительная блокировка
  (отсекли реального зрителя) для него дороже, чем пропущенная накрутка:
  она смещает выборку и портит основной продукт. Это влияет на выбор
  порогов, см. документ по дедупликации.

Сознательно **не** входит в скоуп:

- фронтенд (делается отдельно, бэкенд отдаёт JSON API);
- реальный деплой в облако, IaC, Kubernetes-манифесты;
- защита от мотивированного атакующего с пулом прокси (прямо исключено R2).
